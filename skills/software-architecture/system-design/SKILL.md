# System Design

## Objective
Translate requirements into an implementable system architecture.

## Procedure
1. Clarify functional and non-functional requirements.
2. Identify users, workloads, scale assumptions and constraints.
3. Define APIs, data entities and ownership.
4. Design components and service boundaries.
5. Select synchronous and asynchronous communication.
6. Design storage, caching and indexing.
7. Address security, privacy and authorization.
8. Address availability, resilience and disaster recovery.
9. Estimate capacity, latency and cost where inputs permit.
10. Define deployment, observability and operational processes.
11. Document trade-offs and alternatives.

## Rules
Label assumptions explicitly.
Do not invent traffic or scale figures.
Distinguish high-level design from implementation detail.

## Output
Return requirements, assumptions, architecture, data flow,
API outline, deployment, risks, trade-offs and open questions.
