# Database Design

## Procedure
1. Identify entities, relationships and access patterns.
2. Define consistency and transaction requirements.
3. Select relational or NoSQL storage based on workload needs.
4. Design schema, keys and constraints.
5. Plan indexes and query patterns.
6. Evaluate partitioning, replication and scaling.
7. Define backup, recovery and retention.
8. Apply access control and encryption.
9. Monitor query latency, throughput and capacity.

## Rules
Do not choose a database based only on popularity.
Avoid speculative scale assumptions.
Discuss trade-offs among consistency, availability, latency and operational complexity.

## Output
Return data model, access patterns,
database rationale, indexes, scaling and recovery strategy.
